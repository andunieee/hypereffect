Three small applications, written in Rust with the hypereffect crate and compiled to WebAssembly, run here as servers. A renderer built on the JavaScript library draws them with HTML. Everything that passes between the two is shown under Wire.

How it works


Each application is an implementation of the App trait from the Rust crate: a hello method that builds the interface, an action method that handles what the user did, and, for the timer, a tick method that lets the server push updates on its own. The wasm_app! macro exports it from a module that imports nothing; this page writes the renderer's lines into the module's memory and reads its output back, so the module is the server end of a byte-stream transport.


The renderer side is the Session class from the JavaScript library. It parses lines, keeps the element tree and the signals, evaluates the CEL expressions with its own interpreter, runs handlers and reports which elements changed. A few hundred lines of page code then map each component to HTML: a button to a <button>, a dialog to a <dialog>, a segmented select to a row of toggle buttons.


Things to try:


    
  
  • Change a step size or a task filter. Bound controls write signals locally, and expressions update without contacting the server. The filter is a local signal (_filter), so it is never sent.
    • 
  
  • With latency on, add a task. The button shows Adding… because the action set the _adding indicator, which the server clears in its response.
    • 
  
  • Press Clear completed…. The dialog opens through a local patch; only Delete sends an action.
    • 
  
  • Start the timer. The server sends signal messages on its own, about once a second.
    • 
  
  • Press Disconnect. The last state stays on screen with all controls disabled.
