hypereffect

A small hypermedia protocol for the user interfaces of simple applications. The server describes the screen as a set of components and a set of values; a client renders them with whatever native toolkit it has. HTML, CSS and JavaScript are not required anywhere.

What it is

hypereffect is a line-oriented stream of JSON messages between a server and a renderer. The server sends three kinds of message:

  • element — create an element, or replace the one with the same id.
  • remove — remove an element and everything inside it.
  • signal — patch the shared signal object using JSON Merge Patch (RFC 7386).

The renderer sends back action messages when the user presses a button, submits a field or changes a value that has an action attached. That is the whole loop.

# server → renderer
signal {"count":0}
element {"id":"main","type":"column","gap":"medium"}
element {"id":"label","type":"text","parent":"main","text":{"cel":"'Count: ' + string(signals.count)"}}
element {"id":"inc","type":"button","parent":"main","label":"Add one","onPress":{"action":"increment"}}

# renderer → server, when the button is pressed
action {"name":"increment","signals":{"count":0}}

# server → renderer
signal {"count":1}

The label updates because its text is a CEL expression over the signals. No element was re-sent.

Properties

A fixed component set
Eighteen components — column, row, text, button, input, select, dialog and so on. Renderers implement each one with native widgets. There is no way to define new components from the server.
Variants, not styles
Components carry semantic variants such as h1, caption, success or failure. There are no colours, sizes, fonts or margins in the protocol. Each renderer decides how a failure notice looks on its platform.
Two primitives: elements and signals
Borrowed from Datastar. Elements describe structure; signals hold values. Either can be patched by the server at any time.
Expressions in CEL
Any presentational attribute can be a CEL expression evaluated against the signals. CEL is side-effect free and not Turing-complete, so renderers can evaluate untrusted expressions safely and cheaply.
Server-guided interaction
The application state lives on the server. The renderer knows nothing about the application; it only knows the components, how to evaluate CEL, and how to send an action.
Transport-agnostic
The protocol is newline-delimited text. It can run over WebSockets, HTTP with Server-Sent Events, a Unix socket, stdio, iroh, or anything else that carries ordered bytes.
Embeddable
A renderer is a library that draws into a region its host gives it. A game can show a settings panel, a terminal program can show a form, a desktop app can host a plugin UI — each from a server it does not otherwise understand.

Use cases

hypereffect suits applications whose interface is mostly text, inputs, buttons and lists, and whose logic already lives on a server or in a separate process: settings screens, admin panels, forms, dashboards with a few numbers, internal utilities. Some situations where it is particularly useful:

Sandboxed modules
A WebAssembly module running in a sandbox has no screen of its own. It can write hypereffect lines to its host, and the host's shell renders them and passes actions back. The module talks to the user without linking a UI toolkit or being given access to a window, and the shell keeps control of what is drawn.
Interfaces generated by agents
A hosted LLM agent can produce an interface on the fly — a form to collect the details it needs, a list of options to choose from, a summary with buttons to confirm — and have users interact with it from inside other applications. The component set is small and the format is plain JSON, which models generate reliably, and because there is no scripting the client can display whatever the agent sends without running untrusted code.
Simple services without a custom UI
Many useful services do one straightforward thing and do not need a designed interface. Such a service can just speak hypereffect at a URL. Users then reach it from a dedicated hypereffect browser on desktop, mobile or in a terminal, or from inside an LLM agent's interface, and it looks native in each.
Control panels for hardware
A custom hardware device — a sensor, a lab instrument, a home appliance — can serve its own control panel over a socket, a serial line or the network. The device needs only to write lines of JSON, not to host a web stack, and any renderer can operate it.

What it is not for

  • Applications that need custom visual design or brand-specific appearance.
  • Rich offline behaviour. Without a connection the renderer can only show what it already has.
  • Animation-heavy or canvas-heavy interfaces, games, editors.
  • Replacing the web. If HTML is available and suitable, HTML is a more capable hypermedia.
